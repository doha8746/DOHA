# 필드 매핑표 (네이버 ↔ 한진)

> ⚠️ 아래는 **기본값**입니다. 네이버·한진 다운로드 파일의 실제 헤더는
> 계정/시점/양식버전에 따라 다를 수 있으니, **처음 한 번** 실제 파일 헤더와
> 대조해서 `Config.gs`(Apps Script) 또는 `config.yaml`(Python)만 고치면 됩니다.

## 매핑 개요

| 한진 원클릭 컬럼 | ← 네이버 컬럼 / 규칙 | 처리 |
|------------------|----------------------|------|
| 받는분성명 | 수취인명 | 그대로 |
| 받는분전화번호 | 수취인연락처1 | 전화번호 정규화 |
| 받는분기타연락처 | 수취인연락처2 | 전화번호 정규화 |
| 받는분우편번호 | 우편번호 | 그대로 |
| 받는분주소 | 배송지(통합) | 그대로 |
| 품목명 | 상품명 + 옵션정보 + 수량 | `상품명 (옵션) x수량` 조립 |
| 내품수량 | 수량 | 합산(병합 시) |
| 박스수량 | — | 고정값 `1` |
| 운임구분 | — | 고정값 `신용` (계약) |
| 배송메시지 | 배송메세지(요청사항) | 그대로 |

## 네이버 주문 다운로드 헤더 확인법
스마트스토어센터 → **판매관리 > 발송관리(또는 발주·발송관리)** → 주문 선택 →
**엑셀 다운로드**. 받은 파일 1행(헤더)을 보고 아래 키의 값을 실제 헤더로 맞춥니다.

`Config.gs`의 `NAVER_COLS` / `config.yaml`의 `naver_cols`:
```
receiver        → 수취인명
receiver_phone  → 수취인연락처1
receiver_phone2 → 수취인연락처2
zipcode         → 우편번호
address         → 배송지          (예: '통합배송지', '수취인주소' 등일 수 있음)
product_name    → 상품명
option          → 옵션정보         (예: '옵션', '옵션명' 등)
quantity        → 수량
delivery_memo   → 배송메세지       (예: '배송메시지', '구매자요청사항' 등)
```

## 한진 원클릭 업로드 양식 헤더 확인법
한진택배 원클릭 → **대량접수** → **엑셀 양식 다운로드**. 그 양식의 헤더 순서를
`HANJIN_COLS`(Apps Script) / `hanjin_cols`(yaml)에 **그대로, 순서대로** 넣습니다.
양식에 있는 다른 필수 컬럼(예: 보내는분 정보, 박스타입 등)이 있으면 추가하고,
`MAPPING`에 채우는 규칙을 넣으면 됩니다.

### 보내는분(발송인) 정보 처리
한진 양식이 발송인 정보를 파일에 요구하는 경우가 있고, 원클릭 계정에 미리
등록해두면 파일엔 안 넣어도 되는 경우도 있습니다.
- 파일에 필요하면: `HANJIN_COLS`에 `보내는분성명/전화번호/주소` 등을 추가하고
  `MAPPING`에서 `{ const: '도하커피' }` 처럼 고정값으로 채웁니다.
- 계정에 등록돼 있으면: 파일엔 생략.

## 매핑 규칙 문법 (양쪽 공통)

| 규칙 | 의미 | 예 |
|------|------|-----|
| `{ from: '<네이버키>' }` | 네이버 값 그대로 | `{ from: 'zipcode' }` |
| `{ const: '<값>' }` | 항상 고정값 | `{ const: '신용' }` |
| `{ fn: '<함수>' }` | 계산 | `{ fn: 'phone' }`, `{ fn: 'itemName' }` |

내장 함수: `phone`(연락처1 정규화), `phone2`(연락처2 정규화),
`itemName`/`item_name`(상품명+옵션+수량 조립).

## 자주 조정하는 것
- **운임구분**: 계약(월정산)=`신용`, 선불=`선불`, 착불=`착불`.
- **박스수량**: 대부분 `1`. 다품목 대량이면 규칙 추가.
- **수취인 병합 끄기**: 상품별로 송장을 따로 뽑고 싶으면
  `COMBINE_BY_RECEIVER = false` / `combine_by_receiver: false`.
