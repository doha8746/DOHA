# 설계 · 아키텍처

## 목표
네이버 스마트스토어 주문을 **사람 손을 최소화**하고 한진 원클릭 택배로 넘겨
**주문 → 송장 출력**까지 시간을 줄인다.

## 전체 흐름

```
 ┌─────────────────────────┐
 │ 네이버 스마트스토어      │
 │  · 발송관리에서 주문 확인 │
 └───────────┬─────────────┘
             │  엑셀 다운로드 (지금 단계)  /  커머스API 자동수집 (다음 단계)
             ▼
 ┌─────────────────────────┐
 │ 구글 시트                │
 │  [네이버주문] 탭 ← 붙여넣기│
 │        │ 버튼 클릭        │
 │        ▼                 │
 │  [한진송장] 탭  (변환결과)│   ← 변환 엔진(Apps Script / Python)
 └───────────┬─────────────┘
             │  CSV 다운로드
             ▼
 ┌─────────────────────────┐
 │ 한진 원클릭 택배          │
 │  대량접수 > 엑셀 업로드    │
 │        ▼                 │
 │     송장 출력 🖨️          │
 └─────────────────────────┘
```

## 변환 엔진이 하는 일 (핵심 로직)

| 처리 | 설명 |
|------|------|
| 컬럼 매핑 | 네이버 헤더 → 한진 헤더로 이름/순서 변환 |
| 전화번호 정규화 | 숫자만 추출 후 `010-1234-5678` 형태로. 엑셀에서 앞 0 소실 보정 |
| 품목명 조립 | `상품명 + (옵션) + x수량` 을 한 필드로 |
| 수취인 병합 | 같은 사람이 여러 상품 주문 시 **송장 1건**으로 합치고 품목/수량 합산 |
| 한글 인코딩 | CSV에 UTF-8 BOM 부착 → 한진/엑셀에서 한글 안 깨짐 |

## 두 가지 구현 (같은 로직, 다른 실행 위치)

| 구분 | Apps Script (주력) | Python (보조) |
|------|-------------------|---------------|
| 실행 위치 | 구글 시트 안(클라우드) | PC / 서버 |
| 트리거 | 시트 메뉴 버튼 · 시간 트리거 가능 | 명령어 실행 · cron |
| 강점 | "구글 시트에 바로", 설치 없음 | 대량 파일 일괄, CI/서버 연동 |
| 설정 파일 | `apps-script/Config.gs` | `python/config.yaml` |

두 구현의 매핑 규칙은 **동일한 구조**라 한쪽만 익히면 됩니다.

## 자동화 성숙도 로드맵

**1단계 — 지금(이 기반):** 반자동
- 네이버에서 주문 엑셀 다운로드 → 시트에 붙여넣기 → 버튼 변환 → CSV 업로드
- 즉시 도입 가능, API 승인·계약 불필요

**2단계 — 주문 자동수집:** 네이버 커머스API
- [커머스API 센터](https://apicenter.commerce.naver.com/)에서 앱 등록·판매자 연동 승인
- Apps Script 시간 트리거(예: 10분마다)로 신규 발주 주문을 `네이버주문` 탭에 자동 append
- 사람은 "변환 → 업로드"만. 붙여넣기 사라짐
- 필요한 것: `client_id`, `client_secret` → Apps Script `PropertiesService`에 보관(코드에 하드코딩 금지)

**3단계 — 송장번호 회신 자동화:** 한진 EDI/연계
- 한진 계약(월 정산)·연계 규격 확보 시 접수 결과(운송장번호)를 시트로 회신
- 네이버 발송처리(운송장 입력)까지 자동화 → 완전 무인 흐름

## 보안 원칙
- API 키/시크릿은 **코드·저장소에 커밋 금지**. Apps Script `PropertiesService`
  또는 환경변수로만 주입.
- 개인정보(수취인/주소/전화)는 필요한 시트에만 두고 접근 권한을 최소화.
